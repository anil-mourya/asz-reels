# Unattended footage-led production

Use `pro_renderer.py`, not the older gradient/card renderers. Requirements: Python 3.10+, Pillow, ffmpeg, and DejaVu Sans on Linux (Segoe UI on Windows). Existing cloud environment supplies these. No paid generation, new credentials, or network calls in the renderer.

1. Pull main. Check existing queue, publication log and actual ASZ/Instagram publication history. An empty log with historicalBackfillPending is not proof of no posts. Select a fresh, useful story supported by actual available footage. The archived pipework template is a one-time commissioning edit, not an endless filler reel.
2. Inspect timestamped source frames and audio. Register new owner-authorized footage in `studio/asset-library.json` with SHA-256, truthful observations, clean windows/crops and scene-specific copy. Claude performs this review itself. Never automatically approve unexamined footage or mark a new source owner-archive without verifying its provenance. The current renderer handles reviewed owner-original and owner-archive footage with source audio; it labels them ASZ PROJECT FOOTAGE and PREVIOUSLY RECORDED ASZ FOOTAGE respectively. New source types or narration need an intentionally tested renderer update, not a hidden fallback.
3. Save a dated manifest. Each line and post caption must match this exact asset's reviewed catalogue. `python3 studio/pro_renderer.py render --manifest studio/manifests/<slot>.json` makes video, cover, contact sheet, caption and QA. Processes have timeouts; total render is bounded. Failure leaves publicationReady false. Fix the precise cause once or hold the slot; never post a degraded substitute.
4. Inspect the generated contact sheet (first/last frames and every shot boundary/middle), cover and audio. Write `studio/qa/<slot>-review.json` containing `reviewer`, `reviewedAt`, exact `videoSha256`, one observation per shot, `historyEvidence`, and boolean `checks` for `footage_matches_copy`, `single_clean_logo`, `captions_readable`, `no_old_overlays`, `audio_appropriate`, `cover_matches_video`, `no_false_claims`, `history_checked`. Do not claim mechanical checks prove semantic fit. Claude must actually review the output; this is automated editorial QA, not an owner approval requirement.
5. Run `gate --manifest ... --review ...`. Push the manifest, library updates, outputs, QA and review. Verify raw video and cover URLs. Upload both using the existing ASZ ONE connector and run publish dry-run. Require configured:true and no validation errors. A dry-run is not a post.
6. Pull main again. Run `reserve --manifest ... --review ...` and commit/push the resulting publication-log + queue entry BEFORE the live publish call. If the push conflicts or fails, stop and reconcile; do not publish without a persisted reservation. Do not run overlapping publishing jobs. Exactly one publisher owns a slot.
7. Call existing `publish_instagram_reel` once with assetId, coverAssetId, dryRun:false, confirm:true. On a confirmed result, use `record --manifest ... --status posted --asset-id <id> --media-id <id> --permalink <real-instagram-url>`. Commit/push both records and verify the live result. On timeout/ambiguous response, record publication_unknown, preserve returned IDs, reconcile through the connector/history; do not repeat a publish call. Even a confirmed failure stays reserved until reconciled. A second identical render with another date also fails the content fingerprint check.
8. Update weekly plan with actual theme, archive reuse, result and measured learning. Report the real permalink or exact blocker. Future runs independently repeat this workflow. If no new supported story/footage is available, hold publication and report the missing source; do not recycle the exact edit.

The renderer enforces format, size, decode, audio level, black-frame, sampled motion, source integrity, approved shot/copy mapping, clean crops, logo template and duplicate gates. Creative relevance, meaningful motion, source rights and claims still need Claude's explicit visual/editorial review. The source archive supports installation, not AMC, reports, inspections or test results. Do not insert unsupported safety/compliance advice.

## Shared coordination/reel campaigns (e.g. asz-shared-campaign-*)

This section only clarifies record-keeping obligations for a run driven by the shared SEO/Reels coordination protocol. It adds no new rendering, QA or publication step and changes nothing in steps 1-8 above: every rendering/publication gate (manifest, mechanical QA, independent visual/audio review, gate, dry-run, reservation-before-publish, exactly-once publish, reconciliation) still applies in full, unchanged.

In addition, for such a run:
- Consult the private canonical plan (anil-mourya/asfinance-app, branch marketing-analytics-state, marketing/weekly-plan.json) and marketing/COORDINATION.md there, plus the matching marketing/briefs/<runId>.json, before selecting a story.
- Write a private receipt at marketing/handoffs/<runId>/reels.json on that same private branch for every outcome of the run - posted, blocked, held or skipped alike, never only for a successful post. An unproduced, asset-blocked receipt uses null publication identifiers (assetId, mediaId, permalink, contentFingerprint) and names the exact missing capability; it is never invented to look ready. A held receipt for a run that already completed a real upload or render instead keeps that genuine assetId, contentFingerprint and reservation - only the live mediaId/permalink is null - and must never be read as clear to publish again until reconciled. A run already confirmed posted is reconciled as posted, never overwritten or erased into a held/null record.
- Keep this repository's marketing/weekly-plan.json as a sanitized, explicitly non-authoritative mirror of the canonical plan: generic intent, briefs and confirmed public post details only, never private metrics, queries, audience data, blob hashes, or credentials.
- The private receipt is later read and acknowledged by SEO (marketing/handoffs/<runId>/seo.json on the canonical private branch); do not duplicate, substitute, or pre-write that acknowledgement from this repository.
- Record every timestamp as either a value actually read from a clock or tool response, or null with a note - never a typed/estimated wall-clock time. When only a save time is known, use the git commit's own author date and label it explicitly as commit time, not event time.
